# 批量处理模式

仅在用户明确要求处理文件夹或批量摄入论文时读取本文件。单篇处理不要读取。

## 流程

1. 扫描目标目录中的 PDF。
2. 按 raw 路径镜像规则计算每篇报告的目标路径。
3. 已存在对应报告的论文默认标记为已处理并跳过，避免旧报告因缺少指纹而整批迁移；仅在用户明确要求重新处理时进入单篇流程，由写入状态门禁判断 `LEGACY`、`CHANGED` 或 `UNCHANGED`。
4. 仅在需要排序时用 `pdftotext -l 3` 快速判断主题；该预览不作为论文分析输入。
5. 对未处理论文逐篇执行单篇 Workflow。
6. 每篇结束后只向主会话保留标题、评分、一句话贡献和报告路径。
7. 全部结束后返回处理数量、跳过数量和报告列表。

## 排序

默认顺序：

1. 框架、理论、分类法和基准论文。
2. 方法、系统和特定场景论文。
3. 领域外围或弱相关论文。

用户指定顺序时以用户要求为准。排序的目的只是让后续论文能够利用先处理报告形成的 KB 上下文。

## 文本提取

每篇论文先使用同一个确定性预检脚本：

```bash
bash .claude/skills/paper-ingest/scripts/prepare_pdf.sh "论文路径.pdf"
```

- `PDF_STATUS: OK`：把 `TEXT_PATH` 和完整预检清单传给单篇 Workflow。
- `PDF_STATUS: NEEDS_OCR`：跳过并列入需人工处理清单。
- `PDF_STATUS: FAILED`：跳过并记录简短原因。
- 脚本为每篇论文创建独立临时目录，不共用或覆盖文本文件。
- 预检返回的 `PDF_SHA256` 用于写入前幂等判断；相同指纹不得重复启动或重复落盘。
- 不要把论文正文读入主会话。

## Batch context

主会话只维护：

```text
- 论文标题 | 评分 X/10 | 一句话贡献 | 报告路径
```

总长度不超过 2000 个中文字符。超限时优先保留与当前论文最相关的条目，不传递报告正文、提取稿、实体清单或 Writer 输出。

## 中断恢复

- 每篇 Workflow 独立落盘。
- 恢复时重新扫描报告路径，只处理剩余论文。
- 单批建议不超过 15 篇；更大批次拆分处理。

## 收尾

汇报总数、新处理数、跳过数、每篇报告 wiki-link、评分和一句话贡献，以及合计新建或更新的实体与概念数量。
