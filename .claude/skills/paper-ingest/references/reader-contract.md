# Reader Agent 契约

完整阅读主提示提供的论文文本，生成供下游 Writer 和 Integrator 使用的结构化提取稿。不要写最终报告，不要读写 wiki。

## 执行顺序

1. 检查主提示提供的 PDF 预检清单；只有 `PDF_STATUS: OK` 才继续。
2. 从 PDF 预检清单读取 `TEXT_LINES`，使用 Read 分段读取 `paperPath` 并持续增加 offset，直到读取范围覆盖 `TEXT_LINES` 标明的最后一行；`TEXT_MODE: large` 时同样不得静默截断。无法确认已覆盖最后一行时返回失败。
3. 从正文开头确认准确标题。
4. 判断论文类型：实证研究、理论研究、综述/系统综述、观点/概念论文、方法/系统论文、其他。
5. 覆盖研究问题、方法或论证、证据基础、主要发现与贡献、局限性与不确定性。
   - 方法部分说明关键模块的输入、输出、机制、交互关系、设计动机和成立假设。
   - 证据部分建立“论文主张—实验或论据—结果—可支持的结论”对应关系。
6. 仅在关键结论依赖文本未呈现的图表时，使用 `pdftoppm` 渲染原始 PDF 的相关页面并检查；不要渲染整篇论文。
7. 筛选真正值得创建或更新 wiki 页面的实体与概念。

## 输出格式

可靠读取并完成提取时，严格输出。以下代码围栏只用于展示格式，实际返回不得包含代码围栏或任何前置说明，第一行必须是 `EXTRACTION_STATUS: OK`：

## 实体与概念筛选

条目至少满足以下两项才进入清单：

1. 属于论文核心方法、研究对象或证据来源。
2. 在摘要、方法、结果或结论中反复出现。
3. 可以脱离本文被清晰定义。
4. 未来可能与其他来源形成比较或累积。
5. 对当前 wiki 主题有直接价值。

实体和概念不设最低数量，合计不超过 8 个。没有符合条件的条目时只保留表头。

## 证据规则

- 论文没有实验、消融、公式、数据集或未来工作时，写“论文未报告”或“不适用”。
- 区分论文事实、作者解释、分析者推断和无法确认内容，不把推断写成论文结论。
- 只引用正文中有依据的数字、公式、方法名和数据集名。
- 图表检查只在文本不足以确认核心证据时触发，并在 `VISUAL_PAGES_CHECKED` 中记录页码。
- 不使用 `head` 或固定前 N 行代替全文；长文本通过 Read 的 offset/limit 分段读取。
- 不要把方法压缩成模块名称列表；解释关键机制为什么这样设计、各模块如何共同支撑核心主张。
- 不要把结果压缩成“优于基线”；保留关键指标、数值、比较条件、消融结论及其可支持的结论边界。
- 提取稿通常为 5000–8000 个中文字符；复杂、证据密集的论文可扩展至 10000 字，信息简单的论文可以更短。证据完整性优先于字数，不重复同一结论，不为达到范围填充内容。
- 只输出提取稿，不添加执行说明。
